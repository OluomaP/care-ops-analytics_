# Care Home Operations Analytics

**Does heavy reliance on agency staff go with more incidents and higher costs in care homes, and what sits upstream of it?**

An end-to-end data analyst project: messy data -> cleaning -> SQL -> statistical modelling -> charts -> recommendations. Built around UK adult social care operations, where staffing is the largest cost and a major driver of quality.

> **Read this first: the data is synthetic.** The 24 care homes, staff and incidents are fictional, generated by [`src/generate_data.py`](src/generate_data.py). The generator deliberately builds in a set of assumed relationships ([listed here](docs/data_dictionary.md#relationships-assumed-by-the-generator)). So the findings below show that the **method** recovers a known structure; they are **not evidence about the real care sector**. To use real data, swap in your own tables with the same columns, or see [Next steps](#next-steps).

## Key findings

<!-- FINDINGS:START -->
- **Agency reliance goes with more incidents.** Home-months in the top agency quartile (about 21% of care hours) recorded 12.3 incidents per 1,000 bed days, against 9.3 in the bottom quartile (about 7%): 32% higher. Adjusting for home type, care hours per resident and season, each extra 10 percentage points of agency hours is associated with **16% more incidents** (IRR 1.16, 95% CI 1.08-1.26). Dropping the 18 rows with imputed values gives 1.16, so imputation is not driving it.
- **Medication errors are the most sensitive type** (IRR 1.40, CI 1.26-1.55). Infection shows no clear association (interval includes 1).
- **Agency hours are expensive.** The model puts the premium at about **£13.69 per hour** over permanent staff. Top-quartile home-months cost £180 per bed day against £169, and earned a 12.0% operating margin against 13.7%.
- **The pattern points upstream to pay and vacancy.** Each +5% of pay relative to the local market goes with 4.3pp lower vacancy; each +10pp of vacancy goes with +12.5pp agency share (R² 0.80). Turnover also rises across agency quartiles (28% to 44%), but with only 72 home-years the model cannot separate the roles of vacancy and pay, so I draw no conclusion about which drives it.
- **Winter matters.** The raw incident rate is 20% higher in Dec-Feb (adjusted IRR 1.22, CI 1.18-1.25).
- **Illustrative scenario (2025).** If the 6 homes with the highest agency use (H07, H13, H16, H17, H22, H23) had capped agency share at the 2025 portfolio level (12.4%), the model implies roughly **125 fewer incidents** (10% of those homes' 1,283) and about **£467k** less agency premium. This assumes the association is causal and ignores the cost of recruiting and paying permanent staff, so treat it as an order of magnitude, not a forecast.
<!-- FINDINGS:END -->

### Cleaning log

The raw files contain realistic problems (duplicates, mixed formats, impossible values). Each fix is logged by [`src/clean_data.py`](src/clean_data.py) to [`outputs/tables/cleaning_log.csv`](outputs/tables/cleaning_log.csv):

| table | step | rows | action |
|---|---|---|---|
| monthly_ops | normalise home_id | 53 | strip whitespace, upper-case |
| monthly_ops | standardise month | 87 | parse 'Mon-YYYY' (non-ISO) dates to first-of-month ISO |
| monthly_ops | revenue currency strings | 43 | strip £ and thousands separators, cast to float |
| monthly_ops | drop duplicate home-months | 12 | keep first occurrence of (home_id, month) |
| monthly_ops | impossible occupancy (> 100%) | 4 | replace with home's median occupancy x capacity; flagged occupancy_imputed |
| monthly_ops | missing agency_hours | 14 | impute home's median agency share x total hours; flagged agency_imputed |
| incidents | drop exact duplicate rows | 20 | identical incident_id and all fields |
| incidents | standardise incident_type | 2,011 | trim, case-fold, map plural / abbreviated labels to 6 canonical types |
| incidents | standardise severity | 804 | case-fold to 4 canonical levels |
| incidents | year typos (e.g. 2032) | 15 | swap year digits to recover in-range date |
| incidents | invalid / impossible dates | 3 | drop (e.g. 30 Feb); cannot be recovered |
<!-- CLEANING:END -->

Imputed values are flagged (`agency_imputed`, `occupancy_imputed`), and the main model is re-fitted without them as a sensitivity check.

## Approach

```
generate_data.py  ->  clean_data.py  ->  run_sql.py  ->  analysis.py  ->  charts.py  ->  build_readme.py
 raw CSVs (dirty)     SQLite + view     5 SQL queries    Poisson GLM,     6 PNG charts    fills numbers here
                                                          OLS chain
```

**SQL** ([`sql/`](sql/)): a reusable view joining operations to incidents, then CTEs, `NTILE` quartiles, `RANK()` with `PARTITION BY`, and rolling-window rates (ratio of rolling sums, not an average of ratios).

| Query | What it answers | Techniques |
|---|---|---|
| `01_headline_kpis` | Portfolio KPIs | weighted ratio-of-sums |
| `02_agency_quartiles` | Do high-agency months differ? | CTE, `NTILE` |
| `03_home_scorecard_2025` | Which homes lead / lag? | CTE, `RANK() OVER (PARTITION BY ...)` |
| `04_monthly_trend` | Seasonality and trend | named `WINDOW`, rolling frame |
| `05_incident_mix` | Incident mix by home type | separate aggregates to avoid join fan-out |

**Models** ([`src/analysis.py`](src/analysis.py)), unit of analysis = one home in one month:

- **Poisson GLM with an exposure offset** (`log` occupied bed days): `incidents ~ agency share + care hours per resident + winter + home type`. Rates, not raw counts, because homes differ in size and occupancy. Standard errors are cluster-robust by home. Reported as incident rate ratios (IRR) per +10 percentage points of agency share.
- The same model **per incident type** and for **moderate / severe harm** only.
- **OLS chain** for the upstream story: pay -> vacancy -> agency share -> cost per care hour. Turnover is modelled per home-year because monthly leaver counts are too small and noisy.
- **Sensitivity check:** refit excluding imputed rows.
- **Recovery check:** because the data is simulated, the true assumed effects are known, so the estimates can be audited against them:

<!-- RECOVERY:START -->
| Incident type | Estimated IRR (95% CI) | Assumed true IRR | CI covers truth |
|---|---|---|---|
| Medication error | 1.40 (1.26-1.55) | 1.30 | yes |
| Safeguarding concern | 1.20 (1.07-1.35) | 1.22 | yes |
| Fall | 1.12 (1.01-1.23) | 1.13 | yes |
| Pressure ulcer | 1.26 (1.14-1.38) | 1.11 | **no** |
| Unplanned hospital admission | 1.13 (1.02-1.26) | 1.11 | yes |
| Infection | 1.07 (0.94-1.22) | 1.08 | yes |

5 of 6 intervals contain the assumed value. A miss is expected now and then (with six 95% intervals, at least one miss happens roughly a quarter of the time even when the model is right), and with only 24 clusters robust intervals tend to run a little narrow. I left the miss in rather than re-rolling the seed.

## What I would recommend (as hypotheses to test, not conclusions)

1. **Track pay against the local market as a leading indicator.** It is the strongest upstream correlate of vacancy here. Pilot a pay uplift in two or three below-market homes and measure vacancy, agency hours, incidents and net cost, rather than rolling it out on the strength of this analysis.
2. **Protect medication rounds from agency dependence.** Medication errors show the steepest gradient. Options: require inducted or regular staff for medication rounds, and a short home-specific induction checklist for agency workers.
3. **Staff up for winter.** Infections, hospital admissions and falls rise in Dec-Feb, so plan rotas and bank-staff cover before the peak instead of reacting to it.
4. **Monitor with the home scorecard.** [`03_home_scorecard_2025.sql`](sql/03_home_scorecard_2025.sql) ranks homes on incidents, agency share, cost and margin within their own home type, so a Dementia home is compared with other Dementia homes. Flag homes entering the top agency quartile.

## Limitations

- **Synthetic data.** The relationships are assumptions I wrote into the generator. The analysis can show the method works; it cannot show the care-sector effect is real or its size.
- **Association, not causation.** Even on real data this design is observational. Unmeasured case-mix (resident frailty and dependency), management quality, and reverse causation (a bad incident period driving staff out and agency use up) would all need handling.
- **Only 24 homes.** Cluster-robust standard errors with few clusters can be too optimistic, so the confidence intervals are probably a little narrow. The recovery check above is consistent with that.
- **Costs are modelled, not audited.** The agency premium per hour is estimated by regression; the scenario ignores recruitment, induction and the pay needed to attract permanent staff.
- **Turnover** results are imprecise (72 home-years, vacancy and pay are correlated), so I draw no conclusion from them.
- **Incident counts depend on reporting culture,** which this dataset only partly captures (`reported_within_24h`).

## Next steps

- Replace the synthetic data with real public data (for example Skills for Care workforce estimates and CQC ratings and inspection data) at home or local-authority level; keep the same pipeline and tests.
- Add resident case-mix as a control and a mixed-effects or negative-binomial specification.
- Wrap the scorecard in a small dashboard.

## Reproduce

```bash
git clone https://github.com/OluomaOji/care-ops-analytics.git
cd care-ops-analytics
python -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python run_all.py          # runs everything, regenerates charts and the numbers in this README, then the tests
```

Python 3.11+ (developed on 3.13). Everything is seeded, so results are identical on every run. No cloud services or API keys are needed.
